# AnyCast：跟随 main 分支的一键更新

状态：用户已确认并于 2026-11-15 要求执行。

## 目标与已确认决策

- 用户要求：设置页检查 GitHub 仓库；发现新提交后显示更新按钮，点击后自动更新。
- 用户已确认：以 `main` 分支提交为准，不依赖 GitHub Release。
- 当前仓库：`Fatpandac/AnyCast`，当前启动方式为 `uv run anycast`。
- 版本标识采用运行中服务的 Git SHA，而不是当前固定的 Python 包版本 `0.1.0`。

## 已批准范围

首版支持 macOS / Linux 的单进程、Git 源码部署，保持 `uv run anycast` 入口。新增轻量父进程管理实际服务子进程，负责更新、重启与恢复；不是在请求处理函数中覆盖源码后直接退出。安装本功能后需要手动重新启动一次，后续可在后台更新。

不做零停机、Docker 容器内自更新、Windows 进程管理、多 worker 更新、任意仓库或分支配置、自动无人值守安装、任意历史版本切换。非受管启动方式仍能查看版本，但禁用安装按钮并解释原因。

## 设置页

沿用现有 React / shadcn 样式、字体、配色和设置分区，不重设计其他页面。在运行日志之前增加“应用更新”区：

- 当前运行提交：短 SHA，可打开对应 GitHub 提交。
- 最近检查到的 main 提交：短 SHA、提交标题、提交时间。
- 最近检查时间、检查错误、不可更新的原因。
- “检查更新”按钮；有可升级提交且环境允许时显示“更新并重启”。
- 确认提示说明短暂停机以及下载忙时不能升级。
- 检查失败不显示“已是最新”，也不影响其他设置功能。
- 更新中禁用重复操作，显示“准备更新 / 安装依赖 / 重启中 / 恢复旧版 / 更新失败”。停机时显示重连状态，不误报升级成功。
- 新服务恢复后，只有确认运行 SHA 等于目标 SHA 才显示更新成功。
- 错误摘要显示在此区，详细过程进入现有运行日志；更新器自身的日志在子进程退出期间仍可落盘。

## 检查更新

默认启动后检查一次，此后每小时检查一次；管理员可以主动刷新，后端合并并限制重复检查。检查由后端执行，不把 GitHub 请求交给浏览器。

更新源固定为 `https://github.com/Fatpandac/AnyCast.git` 的 `refs/heads/main`，不依赖用户 SSH 凭据，不修改 origin 配置。通过有超时、非交互的 Git fetch 获取并校验完整 SHA；使用独立更新引用，避免依赖可能过时的 origin/main。网络操作不得阻塞事件循环。

比较当前运行 SHA、工作树 HEAD 和远端 SHA：

- 相同：已是最新。
- 本地是远端祖先：允许快进升级。
- 本地领先、历史分叉、远端强推、运行版本与工作树不一致：解释原因并禁用升级，不强制覆盖。
- 非 Git 工作树、非 main、缺少 Git / uv、代码目录不可写或工作区有修改：保留检查能力或返回明确不可用原因，不能假装支持安装。

工作区检查包含暂存区、已跟踪文件与未忽略的新增文件；忽略配置、数据库、下载和日志等运行数据。不自动提交、stash、清理用户文件或强制 reset。

## 安装与重启流程

1. 管理员确认目标完整 SHA；服务再次验证权限、同源、运行模式和工作区状态。
2. 以原子方式进入独占更新状态。正在下载或扫描时拒绝本次安装，提示稍后重试；进入更新状态后不得启动新的下载或配置写入。关闭“检查后新任务恰好启动”的竞态。
3. 父进程接收固定格式的更新请求；独立校验目标、当前提交、分支及工作区。管理进程间通信仅允许本机私有通道/0600 文件，不开放额外公网管理端口。拒绝重复请求与启动遗留的旧请求。
4. 安装前重新获取 main；若与用户确认目标不同，要求重新检查确认，不静默换成另一个提交。
5. 记录旧 SHA；通过 `git rev-parse --git-path anycast-updates` 定位私有更新目录，在其中保存状态和备份，不让更新器自身的文件触发工作区脏检查。备份 config.yaml 和 database.db（SQLite 使用 backup API）；目录权限 0700、文件权限 0600。备份不进入 Git，也不通过静态资源或 API 暴露。
6. 优雅停止服务，等待退出；超时则中止安装，不在旧进程仍运行时修改代码。普通 Ctrl+C / SIGTERM 仍应停止整个应用，不触发升级或无限重启。
7. 仅快进至已确认 SHA，执行 `uv sync --locked`，使用仓库内已构建的管理前端，不要求安装 pnpm。所有命令使用参数数组、固定可执行程序、固定目录、非交互环境与超时，不执行请求提供的命令或 shell 字符串。
8. 用更新后的虚拟环境启动服务，保持原工作目录、配置位置和服务器端口。管理父进程不依赖可变虚拟环境中的新增模块，服务入口重新解析，不能沿用旧版本 uv console-script 路径。
9. 在有界时间内检查 HTTP 就绪状态与运行 SHA。确认匹配后标记成功并允许后续任务。
10. 升级或启动失败时尝试恢复旧代码、旧锁文件对应依赖，并重新启动旧服务。只在 HEAD 仍是本次目标且工作区没有新增用户修改时回退；否则停止自动文件操作并报告人工恢复步骤。父进程保存失败原因、原 SHA、目标 SHA和恢复结果，即使服务无法启动也能在终端定位。

父进程需防止重复实例更新同一个工作树；重启期间也持有更新锁。启动恢复时不能盲目重放安装请求；根据阶段和记录的 SHA 恢复或明确报错。默认超时：Git 网络操作 30 秒、依赖安装 10 分钟、子进程优雅退出 10 秒、启动就绪 30 秒；超时后记录具体失败阶段，不无限等待。

## 数据与安全边界

- 只有通过现有管理员认证的请求可以读取更新状态或触发操作；写接口沿用同源校验。
- 目标 SHA 必须与服务端已检查的可信 main 提交一致；不接受任意 URL、分支、文件路径或脚本。
- 不覆盖 `config.yaml`、`database.db`、`downloads/`、Cookie 文件或历史日志。
- 日志不得输出认证头、SSH 凭据、Cookie 内容或完整配置。
- 此功能等价于授权可信 main 分支在本机执行代码，不能只因出现新提交就自动安装。
- 下载忙时不执行更新，避免中断在途下载；新版本启动后仍按现有逻辑扫描、调度。
- **回退不是无条件保证**：网络/依赖恢复可能失败。首版不支持不可逆配置或数据库迁移；main 后续变更须保持旧版可读。自动回退不直接覆盖用户数据库，备份用于人工恢复。发生破坏性迁移时必须先扩展迁移和回退协议。
